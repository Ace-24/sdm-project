# Code walkthrough: where each feature lives and how it flows

Generated by `python scripts/walkthrough.py`. Line numbers come from the code itself, so re-run the script after changing code. Click a link to open the file at those lines (works on GitHub and in VS Code).

## How every request flows

1. The browser requests a URL. Flask finds the **route function** in the story's file in `app/boundary/`.
2. The route checks the user's role (`role_required`) and calls the story's **boundary** class (`...Pg`), which reads the form.
3. The boundary calls the **control** class (`...Controller`) in `app/control/`, which validates the input and applies the business rules.
4. The controller calls **entity** classes in `app/entity/`, which read and write the SQLite database (tables in `app/schema.sql`).
5. The result goes back to the boundary, which renders an HTML **page** from `app/templates/` (or a success/error message, or a CSV download).

In the flows below, each line is one method call, indented under the method that calls it, in the order the calls run. Where a step can succeed or fail (e.g. `displaySuccessPg()` / `displayErrorMsg()`), both paths are listed - only one runs, depending on the controller's result.

## Login / Logout

**Actor:** All users

The login form posts the username and password. `LoginController.validateLogin()` finds the account (usernames are not case-sensitive), checks the password hash, and refuses suspended accounts or accounts whose profile is inactive. On success the account ID is stored in the session and a Login entry is written to the activity log. Every request loads the logged-in user (`load_logged_in_user`), and `role_required` blocks pages that belong to other roles (error 403). The customer home page also shows projects from the customer's interests.
